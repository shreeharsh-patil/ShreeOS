# ShreeOS repository audit — 2026-10-09

This report audits source at `276887edf1bf11878473422c534b55093a8ea574`
(`master`). It uses repository configuration and CI results; it does not
substitute source inspection for a built-image or hardware test. The older
[`PHASE1-AUDIT.md`](PHASE1-AUDIT.md) documents a different source-built
baseline and must not be read as the current product inventory.

## Current architecture

The repository contains two separate operating-system build paths:

1. The original cross-built ShreeOS image assembles its own kernel, rootfs,
custom init, package manager and small X11 desktop. `README.md`,
`docs/IMPLEMENTATION-PLAN.md` and `scripts/build.sh` identify it as experimental.
Its installer and update system are not the Debian desktop installer or APT.
2. `prototype/debian-live/` builds a Debian 13 Trixie live image using
`live-build`, `live-boot`, SquashFS, systemd, APT/dpkg and the Debian kernel.
The selectable profiles are console (`base`), XFCE (`desktop`) and KDE Plasma
X11 (`plasma`). `scripts/build-debian-prototype.sh` composes the profiles from
a pinned Debian snapshot. This is the current desktop evaluation path; it is
not yet an install-certified ShreeOS distribution.

## Highest-risk blockers

1. **Install, reboot, and recover:** add a disposable-disk Calamares QEMU
   workflow for empty UEFI/BIOS disks, then verify the installed session,
   account, package database, network and update sources. Keep existing Windows
   partitions outside all test fixtures until a dedicated dual-boot simulator
   proves preservation and failure recovery.
2. **Graphics and session stability:** retain the recent live Plasma
   compositing fix and capture repeated BIOS/UEFI session screenshots. Exercise
   low-effects mode, session restart, lock/login, and supported resolutions.
3. **Updates and package ownership:** validate installed APT signature/expiry
   handling and interrupted operations; package ShreeOS configuration into
   versioned packages before operating an additional repository.
4. **Hardware and release evidence:** build a support matrix from actual
   physical device tests. Do not imply stable dual-boot support from QEMU alone.
5. **Identity:** replace the old letterform logo with an original abstract
   emblem, make vector and raster variants, and verify them in the live boot,
   installer, greeter and desktop.

## Design reference notes

Apple's current macOS guidance emphasizes spacious high-resolution work,
multiple input modes, smooth app/window transitions, file management, menu-bar
and Dock roles, personalization and clarity. ShreeOS should translate those
interaction principles through KDE/Plasma and its own licensed assets. It must
not copy Apple artwork or imply Apple compatibility. Sources:
[Designing for macOS](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/),
[Windows](https://developer.apple.com/design/human-interface-guidelines/windows/),
and [the Mac desktop, menu bar, and Dock](https://support.apple.com/guide/mac-help/desktop-menu-bar-and-dock-mchlws12345m2/mac).
